# Retry Policy · 失败兜底协议

> 11 号「流程工程团队」的输出口径。项目化副本写入 `_meta/retry-policy.md`。

---

## 一、失败判定

下列情况视为"团队失败"：

| 情况 | 判定 |
|------|------|
| 模型/工具返回 429 | ✅ |
| 模型/工具返回 5xx | ✅ |
| 请求超时（>120s 无响应）| ✅ |
| 团队超 SLA（subagent 超过预算时长）| ✅ |
| 输出被审核拒绝 | ✅（同时进 Gate G 重写流程）|
| 输出格式不符合 Gate 检查清单 | ✅ |

---

## 二、重试规则

### 2.1 标准重试

```
失败 → 等待 60 秒 + 0~10 秒随机抖动 → 重试
最大重试 3 次
```

### 2.2 非幂等写操作

任何非幂等的写操作（例如发布到平台、调用付费 API）：
- **必须有幂等性保障（如 idempotency key）才允许自动重试**
- 没有幂等保障 → 禁止自动重试 → 直接进降级流程

---

## 三、降级路径

3 次重试仍失败 → 按下表降级：

| 失败类型 | 降级方案 |
|---------|---------|
| 模型/工具返回错误 | 1) 换 tool（同类替代）→ 2) 主控补齐手写 → 3) 转人工 |
| 团队超 SLA | 1) 缩小范围（只做 Top1）→ 2) 主控补齐 → 3) 转人工 |
| 审核拒绝（Gate G）| 重写策略，按 [`safety-wordlist.md`](safety-wordlist.md) E.2「换语义不只换词」 |
| 反复审核拒绝（>3 次）| 转 Gate B 重新设计场景 |

---

## 四、记录

每次失败 + 重试 + 降级，必须写入：

| 文件 | 内容 |
|------|------|
| `_meta/change-log.md` | 时间 / Gate / 团队 / 失败原因 / 处理结果 |
| `_meta/risk-register.md` | 如果是新型失败（之前没遇到过），记入风险登记 |

---

## 五、对应规则更新

如果失败暴露出 references/*.md 缺规则：
1. 立即更新对应 references/*.md
2. 把更新摘要写入 `_meta/change-log.md`
3. 通知所有团队（在 user-requirements.md 追加更新声明）

> 这是"踩坑→形成规则"的闭环。13 集 `$5B BOYFRIEND` 的 [`pitfalls.md`](pitfalls.md) 就是这样累积出来的。
